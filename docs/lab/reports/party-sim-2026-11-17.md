# Party mode sync: host simulation against the boards (2026-11-17)

`firmware/test/sim_party.c` (hifi-receiver PR 221) runs the follower's real C code: `hifi_party_sync` (TSF and DAC fits, CLOCK, target) and `hifi_party_render` (±1 frame slips, the 5 ms jump, mute). A leader and a follower are simulated with crystal drift, a shared AP TSF, I2S DMA, and Wi-Fi loss and jitter. A case fails if p99 |error| is over 100 µs, if there is an audible step (a jump, or a mute longer than the case allows), or if more than 1% of any 10 s window is over 100 µs. Two deliberately broken servos must fail: sign-flipped gives p99 40 ms, and no slips gives 3 ms. `make test` runs all of it.

The boards land at about half the simulated p99. The simulation's noise models (DAC estimate, jitter) are set wider than the boards show, so it is the harder test. The 10 min run's Wi-Fi drop is the only board test of a lost-clock burst. No board run had a TSF step or a roam, so those cases have only the simulation behind them so far.

PR 221 merged as 95d9712. The merged fit is two commits past 65dbcc2: off-line TSF windows are dropped, and the refit reads its ring in order. The boards ran 65dbcc2, so the 30 min run in "Party mode you can switch on" will be the first on the merged code.
